# 推荐复盘指南（能力 #12 的策略有效性校验）

> **什么时候读这份文档**：当需要回答「之前推荐的股票后来涨了还是跌了」「这套选股策略到底准不准」「要不要改策略参数」时。
> 配套脚本：`scripts/review_picks.py`（可直接运行，无需手写解析）。

---

## 一、为什么必须做复盘

「精选 N 股推荐」每天都在产报告，但**报告本身不会告诉你它准不准**——只有一个有效样本池，才能回答三件事：
1. 这套策略的胜率与盈亏比到底是多少；
2. 亏损/盈利集中在什么特征上（以及**那些特征是不是真能用**）；
3. 哪一条纪律真正有效、哪一条只是听起来有道理。

⚠️ **不做复盘就改策略 = 凭印象改参数**，几乎必然过拟合。

---

## 二、口径（必须先定死，否则数字会被误读）

| 项 | 定义 | 为什么这样定 |
|---|---|---|
| 建仓 | 推荐日**次一交易日的开盘价** | 读者最早能执行的价格（推荐在收盘后发布） |
| 平仓 | 最新可得交易日收盘（`--end` 可指定） | 统一 horizon |
| 收益 | 平仓价 / 建仓价 − 1 | — |
| 基准 | 沪深300（`000300.SH`）同期、同建仓日开盘口径 | 分离 α 与 β（市场普跌时亏损未必是选股问题） |
| 样本 | 全部历史推荐期 | 样本越少结论越弱 |

### ⚠️ 三条必须随结论一起声明的局限
1. **持有期口径冲突**：报告正文通常写「只做回踩、不追高」，而复盘按「次日开盘买入」计算 → **这不是照报告纪律执行的结果**，而是"照最粗暴方式买入"的结果。两者差值本身就是一条结论。
2. **未计交易成本**：手续费 + 印花税 + 滑点，实际每笔再低约 0.1~0.3pct。
3. **持有期可能未走完**：策略定义 3~10 个交易日，最新一两期样本尚未到期，属**中途评估**。

## 三、脚本用法

在工作区根目录执行（需已安装 hithink-finance CLI 且本地库已同步）：

```bash
# 默认：扫描 精选*推荐_*.html，平仓到本地库最新交易日
python <skill>/scripts/review_picks.py

# 指定平仓日 / 自定义报告通配 / 落盘明细
python <skill>/scripts/review_picks.py --end 2026-09-16 --pattern "精选*推荐_*.html" --json review.json
```

输出：逐笔明细表 → 汇总（胜率 / 平均 / 中位数 / 最好最差 / **剔除最大盈利单笔后**）→ **各离场规则对比** → 样本局限提示。

### 🔴 解析历史报告的两个致命坑（脚本已处理，改造时务必保留）
1. **同一日期可能有「验证前 / 验证后」两份报告**：例如 `精选5股推荐_20260908.html`（验证前，含后被 #8 剔除的标的）与 `精选5股推荐_20260908_验证版.html`（**最终交付版**）。**复盘必须用最终交付版**。
2. **必须匹配「推荐卡结构」，禁止「抓全文所有代码」**：报告正文/证据矩阵里会提到很多**未入选**的股票。正确的标记是 `class="nm"` + `class="tcode"`，且**必须容许额外属性**——历史报告曾被注入 `data-page-node-id="…"` 插在 `class="no"` 与 `class="nm"` 之间，正则一严就匹配不到，退化成"抓全文"→ **把被剔除的标的当成推荐**（本项目真实踩过，导致结论全部偏移）。

## 四、首次复盘（2026-09-16，4 期 20 笔）的结论

样本：09-08 / 09-09 / 09-10 / 09-11 四期「精选5股推荐」，09-08 取验证版最终名单；口径＝次日开盘买入 → 09-16 收盘。

### 4.1 总体
| 指标 | 数值 |
|---|---|
| 胜率 | 9/20 = **45.0%** |
| 平均收益 | **−1.73%** |
| 中位数 | −0.63% |
| 最好 / 最差 | +11.73% / **−13.65%** |
| **剔除最大盈利单笔后** | **−2.43%（比原来更差）** |

分期超额：09-08 **−0.01%** / 09-09 **−2.11%** / 09-10 **−0.87%** / 09-11 **+0.41%**
→ 四期**均未显著跑输**，且**收敛、最新一期转正**；同期沪深300 为下跌（−2.15% ~ +0.12%），组合亏损主要来自 β。

**「剔除最大盈利单笔后更差」这条很重要**：说明这套推荐**不存在"靠一笔撑起来的假优势"**，反而是最赚的那笔在替整体扛亏。这与回测引擎里"单笔驱动的假优势"是同一类检验，**任何策略评价都应先做这一步**。

### 4.2 ⚠️ 最重要的一条方法论教训：**事后归因 ≠ 可执行规则**
第一眼看到的图景极有说服力：亏损榜清一色农业链/资源链（粤桂 −13.7%/−13.0%、北大荒 −11.3%、神火 −6.7%、云铝），盈利榜清一色右侧突破（三孚 +11.7%、生益 +7.6%/+6.5%、金安国纪 +5.0%、中际旭创）。

按这个分组：左侧 −8.90%（胜率 1/9）vs 右侧 +2.80%（8/10）——看起来很能指导决策。

**但换成「推荐日当天就能算出来的特征」再分组，全部失效**：

| 分组规则 | n | 平均收益 | 胜率 |
|---|---|---|---|
| 20 日动量 ≥ 0 | 15 | −3.89% | 33.3% |
| 20 日动量 < 0 | 4 | **+1.55%** | **100%** |
| 当日收涨 | 15 | −3.24% | 46.7% |
| 当日收涨 且 贴近 20 日高 | 12 | **−4.16%** | 41.7% |

→ **动量、当日涨跌、均线位置、距高点距离全部无区分力，20 日动量甚至反向**。那个漂亮的"左侧/右侧"是**看着结果回头贴的标签**，没有可执行内容；而"100% 胜率"那组只有 4 笔，**无统计意义**。

→ 更要紧：**"按动量剔除弱势股"会恰好把有效形态全部滤掉**——回测出的两个有效策略（海龟唐奇安 +79.0%、W底双底突破 +76.3%）都是"深跌后突破确认"，候选天然 20 日动量为负。

**这条教训适用于所有策略讨论：一个分组如果只在事后成立、换成事前可算的特征就失效，它就不是规则，只是故事。**

### 4.3 硬止损：有效，但**具体档位区分不出来**
| 离场规则 | 平均 | 胜率 | 最差单笔 |
|---|---|---|---|
| 持有到期末 | −1.73% | 45.0% | **−13.65%** |
| 收盘跌破 MA5 离场 | −2.22% | 25.0% | −9.00% |
| 收盘跌破 MA10 离场 | −1.79% | 30.0% | −9.00% |
| 固定止损 −5% | −1.55% | 35.0% | **−5.00%** |
| **固定止损 −8%** | **−1.02%** | 45.0% | −8.00% |

1. **加硬止损能改善均值并压缩尾部**——这是数据支持的。
2. **「跌破均线就走」反而更差**：阴跌中均线一路下移、迟迟不触发；震荡里又频繁被打掉（胜率 45% → 25%/30%）。**"离场要有上限"，但"用均线当离场条件"并不是好办法。**
3. ⚠️ **−5% 与 −8% 的差异（−1.55% vs −1.02%）落在 20 笔样本的噪声内**，**不足以定优劣**。结论只能到"必须有硬上限"这一层，**不可声称某个具体档位最优**。

### 4.4 报告内部的自相矛盾（结构性问题）
同一张卡片上：`plan.entry` 写「次日开盘（参考 X）」，正文 `why/tnote` 又写「只做回踩、不追高」——**读者无法同时遵守**。

### 4.5 重复推荐 / 集中度
- 某标的**连续 4 期上榜**（本质是同一个下注重复 4 次，不是 4 个独立机会）；
- 某标的**连续 2 期上榜且两次都亏**。

## 五、由复盘推出的改进（已落进 `gen_reco_picks.py`）

| # | 改进 | 依据强度 |
|---|---|---|
| 1 | **止损必须有硬上限**：止损价 = max(支撑位×0.99, 入场参考价×(1−止损幅度)) | ✅ 数据支持（但档位取更保守的 −5%，不宣称最优） |
| 2 | **每张卡追加「执行前提（不满足则不做）」**：次日高开 >3% 放弃；回踩到位且缩量企稳才买；不回踩则不做；与正文冲突时以执行前提为准 | 🟡 逻辑一致性（消除 4.4 的矛盾） |
| 3 | **同一标的 5 个交易日内不重复推荐**（除非出现全新更强的触发信号，并在验证记录留痕） | 🟡 组合纪律（针对 4.5） |

### ❌ 明确**不要**做的（数据不支持，会过拟合）
- 按「板块退潮」剔除候选
- 按「20 日动量 < 0」剔除（**方向反了**）
- 按「当日涨跌」或「距高点距离」筛选

## 六、复盘节奏建议

- **每周跑一次**：`python scripts/review_picks.py --pattern "精选*推荐_*.html"`
- **累积到 50~100 笔再谈"策略是否有效"**，并在此之前**不要**按特征切分去改策略；
- 每轮复盘后，把新增的坑补进 `references/CLI与数据坑清单.md`，把新结论补进本文档第四节。
