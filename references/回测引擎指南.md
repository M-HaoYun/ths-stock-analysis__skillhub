# DuckDB 回测引擎 · 快速指南（能力 #1）

本指南是 `SKILL.md` 能力 #1 的详细参考，回测任务时按需加载。

## 一、引擎能力一览

| 能力 | 命令 |
|------|------|
| 跑单个策略 | `python <skill>/scripts/bt_backtest.py --strategy <id>` |
| 跑全部 20 个内置策略 | `python <skill>/scripts/bt_backtest.py --all` |
| 限定标的池（单股票/自选池） | `python <skill>/scripts/bt_backtest.py --all --universe 002506.SZ,600809.SH --tag mypool` |
| 渲染单策略报告 | `python <skill>/scripts/gen_backtest_report.py --strategy <id>` |
| 渲染标的池验证报告 | `python <skill>/scripts/gen_backtest_report.py --strategy <id> --tag mypool` |
| 指定报告输出目录 | `python <skill>/scripts/gen_backtest_report.py --strategy <id> --out reports` |
| 跳过数据就绪检查（慎用） | `python <skill>/scripts/bt_backtest.py --strategy <id> --force` |

> ✅ **路径约定（v3.5 起，坑 36 已修复）**：**策略定义 = 脚本同目录的 `strategies.json`**（始终以 skill 内版本为准，工作区无需同步副本）；**数据与产物 = `<工作区>/.workbuddy/output/`**（不存在时自动创建）。
> - 跑脚本前设 `THS_WORKSPACE=<工作区绝对路径>`（未设置=当前运行目录）。跨目录调用示例：
>   `THS_WORKSPACE="D:\<工作区>" python "<skill>\scripts\bt_backtest.py" --all`
> - 两个脚本启动时都会打印**实际使用的策略定义路径与策略个数**，可据此确认读的是哪一份。
> - **运行规范**：以后一律**直接用 skill 里的脚本**跑，不要把脚本复制到工作区再跑——优先保证 skill 正确。
> - 可用环境变量 `THS_STRATEGIES` 指向自定义策略文件（覆盖默认同目录）。

**输出文件**（均在 `<工作区>/.workbuddy/output/`）：
- `bt_result_{id}.json`（单策略回测结果，含每笔交易 name/signal_date/cand_cnt/equity）
- `bt_all.json`（全策略汇总，驱动报告 06 横向对比区）
- `DuckDB回测引擎_{策略名}_{YYYYMMDD}.html`（最终报告，默认输出到**工作区根目录**，可用 `--out` 改）

## 一·补充、数据就绪检查（回测启动自动执行）

`bt_backtest.py` 每次启动先做 3 项检查，不满足则打印方法并**交互式询问「是否先更新数据再回测？」（y=更新后重跑 / n=跳过检查继续 / q=退出；非交互环境默认退出）**：

| 检查项 | 判定 | 不满足时的处理（自动打印） |
|---|---|---|
| ① DuckDB 本地库初始化 | `%LOCALAPPDATA%\hithink-finance\data\market.duckdb` 存在 | 签预签名 URL 下载 daily-k+adjustment-factors → `hithink-finance data init --kline <文件> --events <文件>` → `data status` 验证 |
| ② 回测数据存在 | `bt_qfq_1y.parquet` 存在 | 先初始化本地库，再 `db export --sql "SELECT thscode,date,open,high,low,close,volume,amount FROM v_daily_qfq WHERE date >= '<回测开始前120个交易日>'" --output bt_qfq_1y.parquet --file-format parquet` |
| ③ 数据新鲜度 | 最新交易日距今 ≤30 天 | `hithink-finance data status` 查落后天数 → ≤7 交易日 `data sync` 增量 / >7 交易日全量重拉（同 init）→ 重新导出 parquet |

通过时打印：`数据就绪检查 ✓：DuckDB 已初始化 · 回测数据最新 <日期>（N 天前）`。
交互选择：y=去更新（完成后重跑）/ n=跳过检查继续（警告）/ q=退出；自动化场景可 `--force` 跳过交互直接继续（结果可能基于缺失/过期数据，慎用）。

```json
    }
  ]

```

## 三、内置信号 ID 速查

**买入信号（buy_signal）**：

*趋势/突破类*：`ma_cross`(MA5金叉MA20) / `ma20_break`(放量站上MA20) / `channel_break`(突破前20日最高) / `boll_break`(突破布林上轨) / `new_high`(120日新高) / `ma_squeeze_break`(四均线粘合≤3%后突破) / `gap_up`(向上跳空≥2%未回补+放量)

*回踩/低吸类*：`bull_retrace`(多头排列回踩MA20) / `shrink_pullback`(多头排列缩量回踩MA5/MA10) / `strong_pullback_ma20`(站上MA60缩量回踩MA20) / `limit_gene_pullback`(涨停基因缩量回踩MA20) / `first_red_pullback`(连阳≥3后首阴低吸)

*超跌/反转类*：`rsi_oversold`(RSI<30) / `new_low_rebound`(60日新低+收阳) / `boll_lower_buy`(触及布林下轨+收阳) / `rsi_double_bottom`(RSI二次探底回升) / `hammer`(长下影锤子线)

*震荡指标类*：`kdj_golden`(KDJ低位金叉 D≤35) / `macd_golden`(MACD金叉，可限零轴上/下)

*动量/打板类*：`consec_up`(连阳≥3+放量) / `limit_low_open`(昨涨停今低开≥2%) / `streak_2`(二连板+多头+情绪强)

*形态类*：`w_bottom`(W底双底：60日内双底±5%+收盘突破颈线)

**卖出信号（sell_signal）**：`ma_dead` / `close_below_ma5` / `close_below_ma10` / `close_below_ma20` / `close_below_ma60` / `channel_exit`(跌破前10日最低) / `boll_mid` / `rsi_overbought` / `profit_or_time`(止盈+持有到期) / `streak_sell`(当日收阴第3天卖) / `w_fail`(跌破右底/跌回颈线) / `kdj_dead` / `macd_dead` / `macd_bar_shrink`(红柱缩短动能衰竭) / `gap_fill`(跌破前收·缺口回补) / `bear_engulf`(阴包阳)

**新增指标列（v3.4，均可用于自定义信号）**：`bias20`(close/MA20-1) · `cnt_up`(连续收阳天数) · `prev_cnt_up`(昨日连阳数) · `kv`/`kd`/`prev_k`/`prev_d`(KDJ) · `ema12`/`ema26`/`dif`/`dea`/`macd_bar`/`prev_dif`/`prev_dea`/`prev_macd_bar`(MACD 真 EMA 递推，Python 端补算) · `amp5`(5日均振幅) · `amt_ma5`/`amt_ma20` · `prior10_high`/`prior5_low`/`prev_prior20_high` · `prev_rsi14`

**通用风控（所有策略生效）**：单日跌超 `stop_single`、连续阴线累计超 `stop_consec_sum` → 次日开盘卖出；`take_profit` 止盈 / `max_hold` 最长持有天数。

## 四、自定义策略模板（五要素）

用户描述新策略时，先确认五要素（缺项提示补充），再按 `assets/自定义策略五要素模板.json` 填入：

1. 在 **`<skill>/scripts/strategies.json`**（策略定义唯一来源，与脚本同目录）的 `strategies` 数组追加一条（可参照 `assets/自定义策略五要素模板.json`）
2. 选信号：buy_signal/sell_signal 用内置 ID（推荐）或新增信号函数（`bt_backtest.py` 的 `is_buy()`/`check_sell()` 加分支）
3. params 填参数（止损/止盈/持有天数/过滤阈值）
4. 跑 `--strategy <新id>` 验证 → 在 `gen_backtest_report.py` 的 ANALYSIS 字典为该策略写分析文案 → 渲染报告

## 六、关键口径与边界

- 数据：本地 DuckDB `v_daily_qfq` 前复权日K（`bt_qfq_1y.parquet`，含 MA/RSI 预热）
- 涨停：前复权相邻日收益率（主板 +9.8%/创业板科创板 +19.8%）
- 交易：开盘价成交、满仓单标的（仓位可配置）、单边 0.03% 费率（印花税未含）
- 当前资金：初始 100 万按每笔清仓滚动（equity 字段）；总收益含期末未平仓浮动
- 卖出日 = 信号触发日次日开盘成交（策略定义，非延迟执行）
- 候选选择：默认当日成交额最大 1 只，用户可自定义（见 SKILL.md 能力 #1）
- 名称映射（v3.6 起**引擎自动**，坑 41）：本地 `v_symbol.name` 全 NULL → `bt_backtest.py` 启动自动加载 `<工作区>/.workbuddy/output/bt_name_map.json` 回填 `trades.name`；缺失时自动调 `symbol list` 生成，失败回退代码。
  - **症状**：明细「股票」列左右都是代码（如 `601888.SH 601888.SH`）→ 说明 name 未回填 → 跑一次 `bt_backtest.py`（自动重建映射）再渲染报告即可。报告侧已有兜底（缺名称渲染「代码 + 金色待补名称」+ 控制台告警），不会再重复显示两遍代码。
- 0 笔交易边界：胜率 0、盈亏比 None（报告显示 "-"），已兼容
