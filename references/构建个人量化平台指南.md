# 构建个人量化平台指南（附加功能）

> 这是 `ths-stock-analysis` 技能的**附加功能**：把本技能在本地生成的 12 个能力可视化产物，搬到你自己电脑上，做成一个可以点击浏览的本地 Web 平台。
> 它不是「第 13 个能力」，而是一个**复刻工程**：平台不重新画任何排版，只当本技能 `scripts/gen_*.py` 脚本的「宿主」——算出数据、注入脚本、运行脚本、把产出的 HTML 原样呈现。
> 本文档按「可复刻」标准写：**照着做，就能在自己的机器上从零搭出一套能浏览 12 个能力报告的平台**；并把几天里真实踩过的坑逐条记下来。

---

## 0. 先说清边界：什么算「平台」，什么不算

本技能自带 12 个能力（回测 / 速览 / 财务 / 估值 / 日历 / 情绪 / 轮动 / 全面分析 / 穿透 / 组合 / 龙虎榜 / 多能力协同选股）。它们各自是一个 `scripts/gen_*.py` 脚本，运行后在本地落盘一个成品 HTML。

「平台」做的事**有且只有一件**：把这些脚本产出的 HTML，集中到一个浏览器界面里，按能力分页、点一下就渲染、进页面先看上次结果。它**不新增任何分析逻辑、不重写任何排版、不扩展任何数据口径**。所有「内容正确性」的保证，来自「原样复用 skill 脚本」这条铁律。

所以本文档不重复讲 12 个能力本身（那是 SKILL.md 的事），只讲「怎么把脚本变成平台」。

## 1. 定位与适用前提

### 1.1 定位

- **这是「附加功能」，不是「能力」**：它让已有的 skill 脚本可在浏览器里浏览，但不进入 12 个能力清单。
- **目标产物**：一个本地 Web 应用，后端把 skill 脚本跑在子进程里、前端用 `iframe` 呈现 HTML、12 个能力各有独立页面、进页面先显示「上次结果」、点「生成」才重算。
- **不是**「产品级量化平台」：不做账户、不做交易、不做实时推送、不做多用户。它是一套**个人本地浏览 + 点选生成**的工具。

### 1.2 适用前提（缺一不可）

| 前提 | 说明 | 验证方式 |
|---|---|---|
| ① 本技能可用 | `<技能目录>/scripts/gen_*.py` 存在且单独可运行 | 见 §8.2 的技能安全性回归 |
| ② hithink-finance CLI 可用 | 命令行能跑 `hithink-finance ...` | `which hithink-finance` / `npm root -g`（**禁止写死路径**，见 §9） |
| ③ 本机有 Python | 建议 3.11+；子进程用 `sys.executable` | `python --version` |
| ④ 本机有 Node | 前端 Vite 构建用；建议 18+ | `node --version` |
| ⑤（仅本地库类能力）本地 DuckDB 已初始化 | 情绪/选股/回测/速览等读本地库的能力需要 | `hithink-finance data status` |

> **CLI 与数据的细节坑（43 条）不在本文复述**，需要取数时务必先读 `<技能目录>/references/CLI与数据坑清单.md`（编号 1–43），按编号引用即可。

## 2. 核心设计决策（最重要的一节，务必先读）

### 2.1 最初走错的路：前端重画 skill 的排版

平台第一版，前端用 React 把每个能力的区块（KPI、表格、卡片、图表）**重新画一遍**。结果用户三次指出：「和 skill 生成的 HTML 差很多、是你自己编的」。具体错法：

- 轮动本应是**固定 26 个板块**，前端却用 `index catalog` 动态拉了 90 个一级行业；
- 区块数量、标题文案、配色、数值口径都和 skill 成品对不上；
- 涨跌红绿在某些模板被写死，出现「跌日也显红」。

**根因不是水平问题，是方法问题**：skill 模板里有大量「随数据变的事实」（数字、日期区间、个股名、档位结论），前端没有这些事实的唯一来源，只能自己编 → 必然漂移。任何「人肉复刻排版」都不可持续。

### 2.2 正确做法：平台当「skill 脚本的宿主」

关键发现：**skill 的 `gen_*.py` 结构高度统一**，且 skill 自己的日更脚本（`build_rotation_*.py`）已经在用「数据区注入」——用正则锚定 `# ===== 数据 =====` … `# ===== 渲染 =====` 之间的区间，替换成自己算好的数据源码，再 `subprocess` 跑新脚本出 HTML。

所以平台只需复刻这个适配器：

```
后端：根据入参算出「数据区源码」
   → 读 skill 脚本原文件，把数据区整段替换成算出的源码
   → 子进程运行注入后的脚本
   → 取它产出的 HTML 文本
前端：用 <iframe srcDoc={html}> 原样呈现，绝不重画
```

### 2.3 为什么「必须这样」，漂移为什么是必然

- **排版事实的唯一来源是 skill 模板**：CSS、区块结构、图表、配色都在 `gen_*.py` 里。前端另起炉灶，等于维护两份会漂移的实现。
- **数据事实的唯一来源是 skill 数据区**：哪些数字、日期、个股名随数据变，只有模板作者（和模板本身）知道。平台算数据、注入数据区，模板负责怎么排——职责干净。
- **结构一致性可机器验证**：复用模板意味着 `<style>` 应逐字节一致、class 多重集 ≈100%（见 §8.1）。这正是「没自己编」的硬证据。
- **逆向不成立**：先有前端、再塞数据，必然要猜模板里哪些会随数据变 → 漏一个就带出旧值 → 用户看到「和这次入参无关的旧数字」。这是本文档第 5 节要根治的。

> **一句话铁律**：改平台前，先读 skill 的 `scripts/gen_*.py` 与成品 HTML，以它为唯一规格；禁止自行扩展口径、禁止「优化」板块数量、禁止前端重画排版。

## 3. 模块设计

后端渲染链路全在 `<平台仓库>/backend/app/render/`：

```
render/
├── registry.py     # 能力注册表：按 CAP_NAMES 元组加载 caps/、读 SCRIPT/NEED_LOCAL_DB/TITLE/build/script_for
├── splicer.py      # 双锚点正则替换「数据区」
├── runner.py       # 子进程运行注入后的脚本，取产物 HTML
├── skillenv.py     # 定位 skill 目录 + 临时输出目录 + 沙箱免疫清理
├── laststore.py    # 「上次结果」持久化（子目录，防被缓存清扫误删）
└── caps/
    ├── rotation.py        # 每个能力一个构建器
    ├── sentiment.py
    ├── ...（12 个，外加 tearsheet/valuation/penetration 的 ETF 变体）
    └── backtest.py
```

### 3.1 registry.py（能力注册表）

职责：把「能力名」映射到「skill 脚本 + 数据构建器 + 元信息」。

约定（`caps/<cap>.py` 模块级属性/函数）：

| 名称 | 类型 | 含义 |
|---|---|---|
| `SCRIPT` | `str` | skill 脚本文件名，如 `"gen_rotation.py"` |
| `NEED_LOCAL_DB` | `bool` | 是否依赖本地 DuckDB（决定门禁 `require_local`） |
| `TITLE` | `str` | 中文能力名（错误文案 / 日志） |
| `build(date=None, symbol=None, n=None, symbols=None, strategy=None) -> str` | 函数 | 返回可注入该 skill 脚本「数据区」的完整 Python 源码 |
| `script_for(...)` | 可选函数 | 一个能力对应多个 skill 模板时（个股/ETF），按入参动态选脚本名 |

`registry` 在导入期就 `_discover()` 扫描所有能力，读取上述字段；未实现（缺 `SCRIPT`/`build`）的降级为「未实现」而非崩服务。

⚠️ **真实实现细节（照源码，别照文档注释的乐观说法）**：`_discover()` 遍历的是 `registry.py` 里写死的 `CAP_NAMES` 元组，不是「扫 `caps/` 目录自动发现」。因此**新增一个能力 = 同时做两件事**：① 在 `CAP_NAMES` 追加名字；② 新建 `caps/<cap>.py`。只建文件不加名字，不会被注册（这条在源码 docstring 里写得偏乐观，以代码为准）。

> `build()` 的 5 个具名参数由 `routes_render.cap_html` 统一透传：`date / symbol / n / symbols / strategy`。构建器用不到的参数忽略即可，但**签名必须接受这 5 个具名参数**。

### 3.2 splicer.py（双锚点替换数据区）

把一段数据源码替换进 skill 脚本的「数据区」，产出可运行源码。

切分规则（与 skill 自带 `build_rotation_*.py` 一致，但更健壮）：

1. **数据区结束锚点**（head 末尾）：优先正则 `#\s*=+\s*数据[^\n]*=+`（如 `# ================= 数据 =================`）；若无，AST 兜底——取模块级 `BASE/DATE/HIST/WEEKDAY` 赋值最末一行的行尾。
2. **渲染区起始锚点**（body 开头）：优先正则 `#\s*=+\s*(渲染函数|渲染|图表)[^\n]*=+`；若无，AST 兜底——模块级第一个 `FunctionDef` 的行首。
3. `new_src = head + "\n" + data_code + "\n" + body`。

任一锚点定位失败（含 AST 也失败）→ 抛**明确业务错误**（带脚本名与已尝试锚点），**禁止静默产出错误 HTML**。锚点顺序异常（数据行不早于渲染行）→ 同样报错。

> **整段替换**是这里最易踩坑的特性：它把「数据区」从锚点到锚点**整段**替换。这要求 caps 的 `data_code` 必须定义模板里出现的**每一个**数据变量（详见 §4）。

### 3.3 runner.py（子进程运行 + 取产物）

- 用 `sys.executable` 子进程运行注入后的脚本，`cwd` 设为本次临时目录。
- 注入环境：`THS_WORKSPACE=<本次临时输出目录>`（gen 脚本用 `BASE = os.environ.get("THS_WORKSPACE", os.getcwd())` 决定输出目录）+ `PYTHONUTF8=1` + `PYTHONIOENCODING=utf-8`。
- 每次渲染用**独立临时目录**（`<CACHE_DIR>/render/<cap>/<uuid>/`），避免并发抢同名输出文件。
- 非零退出 / 超时 / 未产出 HTML → 抛业务错误（附 stderr / stdout 尾部）。
- 超时默认 `QP_RENDER_TIMEOUT=180` 秒（gen 脚本为纯本地模板渲染，正常 <数秒；宽松给足）。
- 运行结束清理临时目录；清理经 `skillenv.safe_cleanup` 包裹（见 §9，沙箱守卫的 `SystemExit` 不会外溢、不会顶掉业务异常）。

### 3.4 skillenv.py（定位 skill 目录 + 临时目录 + 免疫清理）

- skill 脚本目录：环境变量 `THS_SKILL_DIR` 优先；否则 `config.SKILL_SCRIPTS_DIR`；再兜底常量。
- 临时输出目录：`<CACHE_DIR>/render/<cap>/<uuid>/`，每次唯一。
- `safe_cleanup` / `sweep_render_tmp`：对沙箱「移入回收站 + 批量删除守卫」免疫（见 §9）。**只读定位 skill 目录，绝不写 skill 目录**（改坏用户的 skill 是致命事故，见 §8.2）。

### 3.5 laststore.py（「上次结果」持久化）

需求：进页面只显示上次结果，点「生成」才重算。runner 的产物在一次性临时目录里、会被清扫，所以需要稳定落点。

- 存放目录：`<CACHE_DIR>/last/`（**子目录**）。
  ⚠️ 必须是子目录、不能放 `CACHE_DIR` 顶层：`main._cleanup_cache()` 只删 `CACHE_DIR.glob("*")` 中 mtime 超期的**顶层文件**（`f.is_file()`，不删目录）→ 放子目录天然免疫；也不能放 `CACHE_DIR/render/`（那是 `sweep_render_tmp` 的地盘）。
- cap 名白名单：仅 `^[a-z_]+$`（来自 URL 路径参数，防路径穿越 `../`、盘符、点号）。
- 原子写：先写 `last/<cap>.html.tmp` 再 `os.replace`，避免并发渲染时前端读到半个文件。
- 失败不影响主流程：`save` 的 IO 出错只 `logger.warning`，绝不让渲染请求失败。

### 3.6 caps/*.py（每个能力一个构建器）

每个文件负责：复用平台已有 service 取数 → 把数据区的**全部变量**算出来 → `splicer` 注入并运行。

代码风格（以 `caps/rotation.py` 为范本）：

- 模块顶部声明 `SCRIPT / NEED_LOCAL_DB / TITLE` 与 `DATA_VARIABLES`（数据区全部变量名元组，便于自检）。
- 取数完全复用平台 service（如 `rotation_service.get_rotation`），**不重复实现任何计算**。
- 叙事字段（`CFG.verdict*` / `SIGNALS` / `SUMMARY` / `INSIGHT_*`）一律由数据用 f-string 推导，无手写常量。
- 所有字符串经 `json.dumps(..., ensure_ascii=False)` 转义；数值舍入与 skill 一致。
- `build(...)` 返回 `data_code` 字符串（见 §4 的字面量硬规范）。

### 3.7 新增一个能力的标准步骤

1. 在 `registry.CAP_NAMES` 追加能力名（如 `"mycap"`）。
2. 新建 `render/caps/mycap.py`，声明 `SCRIPT = "gen_mycap.py"`、`NEED_LOCAL_DB`（远端能力 `False`、本地库能力 `True`）、`TITLE`。
3. 实现 `build(date=None, symbol=None, n=None, symbols=None, strategy=None) -> str`：
   - 调平台 service（或 CLI）取数；
   - 算出数据区**全部**变量（先读 `gen_mycap.py` 数据区，列出每一个变量名，缺一个就会 `NameError`，见 §4）；
   - 用 `_pylit` 递归生成字面量（见 §4.1），`compile(source, "<data>", "exec")` 自检（见 §4.2）。
4. 跑「占位符差集自检」：模板里出现的 `__X__` 集合必须 ⊆ `data_code` 定义的变量集合（见 §4.3）。
5. 路由**不用改**：`routes_render.cap_html` 已按 `cap` 通用处理，新能力自动有 `/api/cap/mycap/html`、`/last`、`/last/meta`。
6. 前端加一页 + 在 `router.jsx` 的 `PAGES` 加一条（参考 §7.3）。
7. 跑 §8 的全套验收（结构一致性 + 技能安全性回归 + `verify_caps` 全绿）。

## 4. 数据区契约（最容易踩坑处，写细）

`caps/<cap>.py::build(...)` 返回的是**可注入 skill 脚本数据区的完整 Python 源码字符串**——也就是 `DATE = ...`、`SECTORS = [...]`、`CFG = {...}` 这样的一串赋值语句。`splicer` 把它整段塞进锚点之间，再当 Python 运行。

### 4.1 build() 必须返回「Python 字面量」源码，不是 JSON

**坑**：复合数据里有 `true/false/null`（如回测引擎产物的 `adjust/truncated`），如果直接 `json.dumps` 整个结构，产出的是 `true/false/null`——**这是 JSON 字面量，不是 Python 字面量**，子进程一跑就 `NameError: name 'true' is not defined`。

**修法**：递归 `_pylit()`，只让**纯字符串**走 `json.dumps`，其余类型转成 Python 原生：

```python
def _pylit(value):
    if isinstance(value, bool):      return "True" if value else "False"
    if value is None:                return "None"
    if isinstance(value, str):       return json.dumps(value, ensure_ascii=False)
    if isinstance(value, (int, float)): return repr(value)
    if isinstance(value, (list, tuple)):
        return "[" + ", ".join(_pylit(x) for x in value) + "]"
    if isinstance(value, dict):
        return "{" + ", ".join(f"{_pylit(k)}: {_pylit(v)}" for k, v in value.items()) + "}"
    return json.dumps(str(value), ensure_ascii=False)
```

> 注意：`json.dumps` 产 `true/false/null` 而 Python 要 `True/False/None`；`bool` 必须**先于** `int` 判断（`isinstance(True, int)` 为 `True`）。数值用 `repr` 避免浮点字符串噪声（可先 `round(..., 4)` 收敛）。

### 4.2 build() 返回前用 compile 自检

在 `build()` 末尾对拼好的 `source` 跑一遍：

```python
compile(source, f"<{SCRIPT} data_code>", "exec")
```

这样能在**子进程运行之前**就抓出语法/字面量错误（比如漏了 `_pylit` 导致 `true` 残留），错误信息直接指出第几行第几列，而不是让子进程炸成 `NameError` 后退化成前端裸 500。

### 4.3 splicer 是「整段替换」→ caps 必须定义模板里出现的每一个 `__占位符__`

`splicer` 把数据区从锚点到锚点**整段替换**。skill 模板里大量用 `TPL.replace("__X__", X)` 这类写法。如果 caps 的 `data_code` 没定义 `X`，则模板渲染时 `X` 未绑定 → `NameError`。

**历史事故**（真实）：`penetration` 的 `INST_PERIOD` / `penetration_etf` 的 `REPORT_PERIOD` / `portfolio` 的 `MONTHLY_TITLE` —— 三个能力因为 caps 没定义模板 TPL 新引入的占位变量，全报 `NameError`，导致当轮 3 个能力挂掉。

**修法：占位符差集自检**。caps 在 `build()` 里（或验收时）做一道断言：

- 从模板源码提取出现的 `__X__` 占位符集合 `T`；
- 从 `data_code` 提取定义的变量名集合 `D`；
- 要求 `T ⊆ D`；否则 `T - D ≠ ∅` → 直接报错，列出缺哪些。

> 这条自检是「参数化」工作的护栏（见 §5），也是新增/修改能力后必跑的步骤。

### 4.4 顺带：模板里还有「渲染函数直接引用的数据区变量」

`__X__` 只是 TPL 里 `.replace` 的那部分。模板的**渲染函数（def）还会直接引用数据区变量**（如 `CFG["verdict"]`、`SECTORS[i][2]`），这些变量名往往不以 `__X__` 形式出现，但同样是「数据区必须定义」的。

**更可靠的 needs 计算（推荐）**：用 AST 取「数据锚点 → 渲染锚点」之间的**模块级赋值名**集合，作为模板期望的数据区变量全集。它比「占位符差集」覆盖得更全（包含了 def 里引用的普通变量）。caps 的 `DATA_VARIABLES` 应等于（或超集于）这个集合。AST 做法：

```python
import ast
tree = ast.parse(skill_src)
# 模块级 Assignment / AnnAssign 的 target 名，落在 data 锚点行 ~ render 锚点行之间
# = 模板期望被数据区定义的全部变量
```

> 实操：先 `ast.parse` skill 脚本，收集模块级 `NAME = ...` 的 `NAME`，去掉 `BASE/DATE/HIST/WEEKDAY` 这类常量，剩下的就是 caps 必须赋值的清单。对照 `DATA_VARIABLES` 逐项核对，缺一个补一个。

## 5. 模板参数化硬规范

### 5.1 问题

skill 的 `gen_*.py` 模板里有一批**人工写死的数据事实**（数字 / 日期区间 / 个股名 / 档位结论）。平台换了数据却不换文案 → 页面显示与本次入参无关的旧值。

**真实案例**：`earnings.html` 带出 `3643` / `8/24` / `66.5%`；`lhb.html` 带出 `55%` / `医药/通信/贵金属`；`picks` 带出字面量 `true/false`。

### 5.2 做法（四步）

1. **模板里随数据变的事实 → `__VAR__`**（占位符化）。如 `gen_earnings_calendar.py` 把 `3643`、日期区间、`66.5%` 写成 `__KEY_DISCLOSURE_N__` 等。
2. **同时在 skill 脚本自己的数据区把该变量赋成原值**（保证 skill 单独运行产物不变——这是「没改坏用户 skill」的硬证据，见 §8.2）。
3. 平台 `caps/*.py` 用真实数据算出并注入；**算不出就注入如实的「未取到」文案（如 `[MISSING]`），绝不留旧值、绝不编造**。
4. 定性叙述可保留（如模型输出 disclaimer），但凡随行情变化的展示文字都进数据区。

### 5.3 硬性自验（改完必做三件事）

- skill 单独跑产物**逐字节一致**（见 §8.2）；
- 平台侧渲染通过 + 旧值 `grep` 为 0（见 §8.4 `residue_check.py`）；
- caps 占位符差集自检通过（见 §4.3）。

### 5.4 命名禁忌

产物里除刻意保留的 `[MISSING]` 外，禁止：

- `__xxx__` 残留（占位符没被替换）；
- 落单 `X` / `N` 占位字母；
- 字面量 `nan` / `None` / `NaN`（缺失值显示 `[MISSING]` 或 `—`）。

### 5.5 顺带记一个 skill 模板自身的 bug（供你判断要不要顺手修）

E2E 复核发现 skill 模板把涨跌**颜色写死**：

| 文件:行 | 代码 | 后果 |
|---|---|---|
| `gen_tearsheet_stock.py` | `.hero .chg{color:var(--red)}` | 个股当日涨跌恒红 → 跌日错 |
| `gen_tearsheet_etf.py` | `.hero .chg{color:var(--green)}` | ETF 当日涨跌恒绿 → 涨日也错 |
| 两文件「近1年涨幅」 | 内联 `color:var(--red)` | 负收益也红 |

判据：**同区块箭头是数据驱动的 `__ARROW__`（▲/▼），颜色却写死** → 作者本意要方向、漏了颜色。skill 几份成品恰好全是涨日，bug 从未暴露。**注意：这个 bug 在用户 skill 本身同样存在**——他直接跑 skill 出的速览卡跌日也是红字。是否连 skill 一起修，由你决定（修了会破坏「单独运行字节一致」这条安全证明）。

> 另有：`class="pill up num"` 里的 `up`/`dn` 在多数模板 CSS 里**无定义（死类）**，颜色只来自内联 style。**死类保留别删**（删了动结构指纹，§8.1 的 class 多重集会误判）。

## 6. 日期与数据新鲜度（平台最容易出错的地方）

### 6.1 三套日期口径

| 口径 | 定义 | 用途 |
|---|---|---|
| `calendar.latest_complete_trade_date()` | 日历中 **< 今天** 的最大日期 | 保守的「本地库同步目标」（对齐 `ensure_data.py`） |
| `calendar.latest_published_trade_date()` | 上面基础上**盘后探测远端**（缓存 120s） | 「该日能否取用」判定 → 避免盘后选当天误报 1006 |
| `freshness.latest_local_trade_date()` | `min(最新已发布, 本地库 max(date))` | 读本地库能力的默认日期 |

默认日期：远端能力（轮动/龙虎榜/日历）= `latest_published`；本地库能力（情绪/选股）= `latest_local`。

### 6.2 门禁两条判定解耦（这是 09-14 误报「未发布」的根因修复）

原来把 `latest_complete_trade_date()`（规则=永久排除今天）当成「数据是否已发布」判据并硬编码进 5 个能力默认日期 → 2026-09-14 远端已有 09-14 全量，平台仍报 1006。

`check_gate` 现在两条独立判定：

1. **① 该日是否已发布** → `target > 最新已发布交易日` 或 `target` 非交易日 → `1006`。纯远端能力（传 `require_local=False`）也受此保护，不被本地库拖累。
2. **② 本地库新鲜度** → 仅 `require_local=True` 时校验；落后则自动 `data sync`（对齐 skill `ensure_data.py --yes`）后复验，仍落后且未 `force` → `1005`。

### 6.3 只有显式传 date 才严格拦截

`_lag_trade_days` 必须**含右端**（`latest < d <= target`）；原 `latest < d < target` 两端都不含 → 本地 09-11 相对 09-14 算出 0 天（09-12/13 是周末），自动同步不触发。

**只有显式指定 `date` 才严格 1005**；未指定时自动同步后以「本地可用日」继续（页面照常出「本地可用日」结果并在标题显示该日期），绝不用旧数据静默顶替用户要的那天。

### 6.4 自动同步护栏

- `AUTO_SYNC_ON_STALE`（`QP_AUTO_SYNC=0` 关）+ 落后 ≤ `SYNC_MAX_LAG_TRADE_DAYS`(7) 才增量同步。
- 单飞锁（并发不排队，直接 1005）+ 同目标日 30 分钟内不重复 + 已知包覆盖日 < 目标日则跳过（`data sync` 即使 `decision=SKIP` 也要下载 ~1MiB、耗时**约 2.5 分钟**，重复做毫无意义）。
- ⚠️ **本地同步包次日才含当日行情**：`data sync` 的 `release_id` 是生成日，包内数据 = 生成日之前最近交易日（实测 `release 20260913` 只到 09-11）。所以盘后刚收盘时，轮动（远端指数）已是当天、情绪（本地库）还是前一天——这是数据源差异，不是 bug。

### 6.5 ⚠️ 前端超时必须覆盖后端最慢合法路径（真实事故）

`routes_render.cap_html` 只在**显式传 `date`** 时才走 `check_gate`；而门禁在本地库滞后时会**阻塞执行一次 `data sync`（实测约 2.5 分钟）**，再叠加 skill 渲染（picks/comprehensive 可达 2 分钟）。

`CapReport.jsx` 原超时 `180s` 会在这条路径上提前 abort，把本该成功的请求显示成失败 → **已改 `300s`**。任何走 `check_gate` 的请求都要按「同步 + 渲染」量级给超时。加载文案也改为如实提示「首次可能需要 1–3 分钟，本地数据滞后时会先自动同步一次」。

### 6.6 ⚠️ 用户在用平台时不要在 8000–8039 起额外后端

多个后端进程会抢本地 DuckDB **单文件独占锁**（`cli_runner` 的 `RLock` 只在进程内串行化，跨进程挡不住），把同步/渲染拖到十几分钟，用户会以为卡死。验证一律先确认没有别的实例在跑（见 §9 `lead_kill_ports.py`，但**绝不 kill 用户 :8000**）。

## 7. 前端要点

### 7.1 iframe srcDoc 原样呈现

前端 `CapReport.jsx` 用 `<iframe srcDoc={html}>` 呈现后端返回的 HTML，**不自绘任何能力区块**。这是「不漂移」的前端侧保证。

### 7.2 区分「HTML」与「业务错误信封」

- 成功：HTTP 200 + `text/html` 正文 → `apiGet` 原样返回**字符串** → 直接 `srcDoc` 呈现。
- 失败：HTTP 200 + `{code, data, message}` 信封（业务错误一律 HTTP 200，全局异常处理器负责）→ `apiGet` 抛 `ApiError` → 红色 `ErrorState`（含「重试」/「一键同步」）。

> **所有业务错误走 HTTP 200 + 信封**，不要用 4xx/5xx 表达业务失败（否则前端拿不到 `message`，只能显示裸状态码）。`CapReport` 里还有一道兜底：极少数情况下未抛错却返回 `{code,message}` 信封 → 也走 ErrorState。

### 7.3 12 个能力页的路由

`router.jsx` 的 `PAGES` 定义 12 个能力页（懒加载）+ 总览 + 设置，按 6 组导航分组。注意 ETF 变体（速览/估值/穿透的 ETF）**不是独立路由**，是同一页按 `symbol` 走不同 skill 脚本（页内切换）。所以页面数 = 12，不是 15。

### 7.4 双模式设计（进页面只看上次结果，点生成才计算）

`CapReport` 由 `url` prop 决定模式：

- **计算模式**（`url` 非空）：走 `GET /api/cap/{cap}/html?...`，`timeout: 300000`，错误走红色 `ErrorState`。
- **读取模式**（`url` 为 `null`）：进页面时走 `GET /api/cap/{cap}/last`，成功渲染并在上方显示提示条「显示上次生成的结果 · <generated_at>」；任何失败 → **中性空状态卡片**（不报红）。`/last/meta` 并行取生成时间，失败忽略。

配套后端：`/api/cap/{cap}/last`（有 → `text/html`；无 → 信封 `code=3002`「{cap} 尚无历史报告，请点击「生成」」）+ `/api/cap/{cap}/last/meta`（`ok(meta)`）。

> 注意：进页面时日期类页 `useState(todayStr())`、初值 `null`（点「生成」才 set）；标的类页 `url` 初值 `null`。`todayStr()` 用**本地时间**拼 `YYYY-MM-DD`，严禁 `toISOString().slice(0,10)`（UTC，中国时区 08:00 前差一天）。无「生成」按钮的标的页要传中性 emptyHint（如「在上方搜索并选择标的后即可计算」），别让用户去找不存在的按钮。

## 8. 验证方法论（用户最看重的一节）

### 8.1 结构一致性验证法（核心验收手段）

**不看数据看结构**——只要复用的是同一份模板，结构就应当一致；差异必须能逐条归因到真实数据。

比对三项：

1. **`<style>` 块逐字节比对**：复用 TPL 时应完全一致。
2. **标题序列（h1–h4 文本）比对**：逐项比对。
3. **body 内 class 名多重集比对**：交集/差集（Jaccard 比率）。

判定标准：

- 复用 TPL 时 `<style>` 应**完全一致**、`<style>` 一致 + class 多重集 ≈100%。
- 标题差异若能逐条归因到真实数据（如 5550 vs 5547 只、中报 vs 一季报、白酒 vs 光通信同行、精选 4 股 vs 5 股、个股名不同）→ 合格。

**差异归因做法**（`compare_struct.py`）：用 `difflib.SequenceMatcher` 对齐平台标题序列与基准标题序列，对 `replace/delete/insert` 块逐条人工核对是不是「数据导致」（股票数、报告期、个股名）。class 多重集差集若平台是基准的**真子集**（基准多出的 `mid`/`neg`/`a`/`bad`/`c`/`d` 是负值/档位状态类，本次数据未触发）→ 非结构丢失、非缺陷。

> 工具：`<平台仓库>/.tmp/compare_struct.py`（平台产物 `caps_out/` vs skill 成品 HTML 基准）。

### 8.2 skill 安全性回归（证明「参数化没改坏用户的 skill」）

在**独立临时工作区**（设 `THS_WORKSPACE` 到临时目录，绝不污染 skill 目录）单独运行被改过的 skill 脚本，检查：

1. 退出码 0；
2. 产物无 `__占位符__` 残留（`__[A-Za-z][A-Za-z0-9_]{2,}__`)；
3. 原值关键字仍在（证明默认值接得上、skill 输出未变）。

例：`gen_rotation.py` 必含「板块轮动雷达」；`gen_lhb.py` 必含「基准判断（55%）」/「医药/通信/贵金属」/「普冉股份」；`gen_tearsheet_stock.py` 必含「航天发展」/「000547.SZ」/「2025 年报」等。

14 个 `gen_*.py` 全量跑过，exit 0 + 无占位符残留 + 原值关键字仍在 → 用户的 skill 未被参数化改坏。

> ⚠️ **教训**：12 个 skill 脚本无备份、skill 目录不是 git 仓库 → 无版本历史可回溯。改用户 skill 前先留备份。当前兜底完全依赖「单独运行字节一致」这条性质。
> 工具：`<平台仓库>/.tmp/skill_standalone_check.py`。

### 8.3 「HTTP 契约全绿 ≠ 页面正确」

历史上靠 HTTP 状态/JSON 校验**发现不了**的渲染层缺陷：

- `[object Object]`（把对象当字符串渲染）；
- 裸 JSON 打印（信封被当 HTML 塞进 iframe）；
- 重复卡片（React key 缺失导致列表渲染两遍）；
- **红涨绿跌配色反转**（模板写死颜色，跌日也红/涨日也绿，见 §5.5）；
- iframe 空白（srcDoc 没接到 HTML，接到信封）。

这些**只能靠真实浏览器 E2E + 页面文本扫描**发现。列出历史事故是为了让你知道验收要到哪一环：

- **Route A**（直开 `/api/cap/{cap}/html`）：渲染成功后扫文本。
- **Route B**（前端真实路由 + 轮询等正文 + 截图）：17 个路由（12 能力页 + 总览 + 设置 + …）全部加载、0 阻断。

⚠️ **截图必须等正文真正渲染出来再拍**：渲染 7–130 秒，**抢跑会拍到「正在生成报告…」加载态**等于没验证。第一轮 15 张截图全拍在加载态就是教训。

## 9. 环境铁律与坑清单（具体、带现象与修法）

### 9.1 本机 shell 缺 ls/grep/cd/dirname/tail/head

现象：终端里 `ls`/`grep`/`cd`/`dirname`/`tail`/`head` 直接 command not found；`netstat -ano` 输出是 gbk 需按 gbk 解码。
修法：**目录/进程/端口/文本一律用 Python 脚本**。端口探测用 `socket.connect_ex`；进程端口映射用 `subprocess` 跑 `netstat -ano` 后按 gbk 解码再正则；本地 HTTP 请求必须空 `ProxyHandler` 绕 `HTTP_PROXY`（见 `probe.py`）。

### 9.2 沙箱批量删除守卫（真实事故：9/12 个能力变裸 500）

现象：终端启动的 Python 里 `shutil.rmtree` 被打桩成「移入回收站」，**单 turn 删除数 >50 即 `raise SystemExit(1)`**。
坑：`ignore_errors=True` **拦不住 `BaseException`**（`SystemExit` 是 `BaseException` 子类）→ 会在 `finally` 里炸掉整个渲染，甚至**顶掉**本该抛给用户的 `ApiError`（真实失败原因），最终退化成 FastAPI 裸 500（一次事故里 9/12 个能力变裸 500）。
修法：清理代码必须 `try/except BaseException` 且**只 warning、绝不重抛**：

```python
def safe_cleanup(path):
    try:
        shutil.rmtree(path, ignore_errors=True)
    except BaseException:   # noqa: BLE001
        logger.warning("临时目录清理失败（已忽略）：%s", path, exc_info=True)
```

`runner._safe_cleanup` 与 `skillenv.sweep_render_tmp` 都套了这层。用户双击 `start-all.cmd` 启动时无此桩（只在 Agent 终端会话里有）。

### 9.3 Python duckdb 被 WDAC 拦截

现象：本机策略（WDAC）拦截 `duckdb` 原生包，`import duckdb` 失败。
修法：**只走 CLI**（`hithink-finance db query/export`），需要 SQL 时用子进程 CLI 或垫片。回测引擎依赖 duckdb → 平台用自有垫片产出 `bt_result_*.json`，再交给 skill 的报告生成器渲染（不重跑 `bt_backtest.py`）。

### 9.4 venv 无 pip

现象：虚拟环境里 `pip` 不可用，依赖装不进 venv。
修法：依赖装到 `backend/vendor` 并设 `PYTHONPATH`（见 `run_backend.py`：`sys.path.insert(0, backend/vendor)`）。

### 9.5 rollup 原生二进制被拦

现象：Vite 构建时 rollup 原生二进制被策略拦截。
修法：`package.json` 用 `@rollup/wasm-node` 的 `overrides` 走 wasm 版。

### 9.6 本地 DuckDB 单文件独占锁

现象：读本地库的能力偶发卡住、超时；多进程并发时互相锁。
修法：进程内 `RLock` 串行化所有 DuckDB 访问 + 退避重试。**多后端进程会互相抢锁**（跨进程 `RLock` 挡不住）→ 验收前先清端口（`lead_kill_ports.py`）；**用户实例在跑时不要再起第二个后端**（§6.6 事故：请求被拖成「卡住」十几分钟）。

### 9.7 前端构建必须在前端目录内执行

现象：在仓库根跑 `vite build` → Tailwind 找不到 `tailwind.config.js` → **工具类全丢、CSS 只剩约 5.8kB**（正确约 17kB）。
修法：先 `os.chdir(frontend)` 再 `vite build`（`build_frontend.py` 即此做法）。产物核验：CSS ≈16.99kB、模块数（如 657）、无旧超时残留。

### 9.8 后端必须单 worker

现象：多 worker 下 DuckDB 锁、临时目录、状态缓存都会乱。
修法：`uvicorn.run(..., workers=1)`（`run_backend.py` 已固定）。

### 9.9 验证一律用非默认端口；绝不 kill 用户自己的进程

现象：在 8000–8039 起额外后端会和用户实例抢 DuckDB 锁（§6.6）。
修法：验收用 8031–8039 之类非默认端口；清端口用 `lead_kill_ports.py`（硬性 `PROTECT={8000}`，**绝不动用户 :8000**）；用户 :8000 是管理员权限进程，kill 会被拒，须由用户在管理员窗口重启。

### 9.10 缓存清理边界

现象：需要持久化的「上次结果」被缓存清扫误删。
修法：`laststore` 用 `<CACHE_DIR>/last/` **子目录**（§3.5），天然躲开 `main._cleanup_cache()` 对 `CACHE_DIR.glob("*")` 顶层文件的删除。别把持久化文件放在会被清扫扫描的目录（`cache/last/` 用子目录规避顶层清扫；`render/` 是 `sweep_render_tmp` 地盘，也别放）。

### 9.11 主题色细节（前端写错会静默丢样式）

- `tailwind.config.js` 令牌：`brand #1f3a93` / `gold #c9a227` / `up #e5484d`（涨红）/ `dn #2fa36b`（跌绿）/ `hot #e5484d` / `ink #1f2733` / `muted` / `line` / `page`。
- ⚠️ **没有 `ink-3`**：`ink` 是扁平色、无 `-3` 档位，写 `text-ink-3` 不生成任何类。
- 涨跌配色规则（A股红涨绿跌）：个股涨跌一律 `chg_cls()` 判类、禁止硬编码类名；「市场热度」类（涨停家数/封板率/连板高度）恒 `.hot` 红、不受当日方向影响；跌停/降温类用 `.dn` 绿。

## 10. 从零复刻的步骤清单

按顺序执行（每步跑通再进下一步）：

1. **准备环境**：确认 hithink-finance CLI 可用（`which hithink-finance`）、Python/Node 就绪；本地库类能力先 `data sync` 一次。依赖装 `backend/vendor` + `PYTHONPATH`（§9.4），前端 `package.json` 加 `@rollup/wasm-node` overrides（§9.5）。
2. **起后端（单 worker）**：`python .tmp/run_backend.py 8037`（或自己写启动器，必须 `workers=1`）。
3. **跑通第一个能力（rotation，纯远端最稳）**：实现 `caps/rotation.py`（`SCRIPT="gen_rotation.py"`、`NEED_LOCAL_DB=False`），`build()` 复用 `rotation_service.get_rotation`；`GET /api/cap/rotation/html?date=2026-09-11` 应返回 `text/html`。用 `probe.py` 验（绕代理）。
4. **结构对照第一份**：`compare_struct.py rotation` 看 `<style>` 是否逐字节一致；不一致说明你写了模板没复用的东西，回去读 `gen_rotation.py`。
5. **加第二个能力（sentiment，本地库）**：`NEED_LOCAL_DB=True`，体验门禁（`require_local` 校验 + 自动同步）。确认显式选未来日 → 1006、选本地库无数据的当天 → 1005。
6. **实现门禁（freshness）**：接入三套日期口径（§6.1）、`check_gate` 两条解耦（§6.2）、自动同步护栏（§6.4）、前端超时改 300s（§6.5）。
7. **加 skill 安全性回归**：`skill_standalone_check.py` 全量跑 14 个 `gen_*.py`，确认参数化没改坏 skill（§8.2）。
8. **实现前端壳**：`router.jsx` 12 页 + `CapReport.jsx`（`iframe srcDoc` + 双模式 + 300s 超时），`build_frontend.py` 在 frontend 目录内构建（§9.7）。
9. **逐能力迁移**：按 §3.7 把 12 个能力逐个补 `caps/*.py`，每个都过：占位符差集自检（§4.3）+ `compile` 自检（§4.2）+ `residue_check` 0 命中（§8.4）。
10. **实现「上次结果」**：`laststore.py` + `/last`、`/last/meta` 路由 + 前端读取模式（§3.5、§7.4）。
11. **补验证脚本**：`verify_caps.py` 15 用例全绿 + `compare_struct.py` `<style>` 逐字节一致 + 浏览器 E2E（轮询等正文再截图，§8.3）。
12. **打包脚本**：`scripts/start-all.cmd`（起后端新窗口 → 等 health → 起前端），前端 `start-frontend.ps1` 用 `vite`（dev）或 `build` + `preview`（prod）。**绝不写死 CLI/node 路径**（§1.2、CLI 坑 22）。

## 11. 坑速查表

| 现象 | 根因 | 修法 |
|---|---|---|
| 平台报告与 skill HTML 差很多、像自己编的 | 前端重画排版、数据事实无来源 | 平台当 skill 脚本宿主，只注入数据区、iframe 原样呈现（§2） |
| 渲染报 `NameError: name 'true' is not defined` | `json.dumps` 产出 `true/false/null` 非 Python 字面量 | 递归 `_pylit()`，bool/None 转 `True/False/None`（§4.1） |
| 能力挂掉 `NameError: name 'X' is not defined` | caps 没定义模板 TPL 新引入的占位变量（splicer 整段替换） | 占位符差集自检 `T ⊆ D`（§4.3） |
| 页面带出旧数字（如 `3643`/`55%`） | 模板数据事实写死未参数化 | 模板 `__VAR__` + 数据区赋回原值 + 算不出写 `[MISSING]`（§5） |
| 盘后选当天报「数据未发布」1006 | 把 `latest_complete`（排除今天）当发布判据 | `latest_published` 盘后探测远端（§6.2） |
| 点生成一直「正在生成」最终失败 | 前端 180s 超时 < 门禁同步 2.5min+渲染 | 前端超时改 300s（§6.5） |
| 请求被拖成「卡住」十几分钟 | 多后端进程抢 DuckDB 单文件锁 | 验收清端口、不在 8000–8039 起第二个后端（§6.6/§9.6） |
| 9/12 能力变裸 500 | 清理 `shutil.rmtree` 触发沙箱 `SystemExit` 顶掉 `ApiError` | `try/except BaseException` 只 warning（§9.2） |
| 前端 CSS 只剩 5.8kB、样式全丢 | 在仓库根 build，Tailwind 找不到 config | `chdir(frontend)` 再 `vite build`（§9.7） |
| `import duckdb` 失败 | WDAC 拦截原生包 | 只走 CLI / 垫片（§9.3） |
| venv 装不了依赖 | 环境无 pip | 装 `backend/vendor` + `PYTHONPATH`（§9.4） |
| rollup 构建报错 | 原生二进制被拦 | `@rollup/wasm-node` overrides（§9.5） |
| 本地 HTTP 请求被代理吞/超时 | 本机 `HTTP_PROXY` | 请求用空 `ProxyHandler`（§9.1、`probe.py`） |
| 进页面报错而非显示上次结果 | 读取模式失败走红 | 读取模式任何失败 → 中性空状态（§7.4） |
| 截图全是「加载中」 | 抢跑拍摄 | 轮询等正文真正渲染再拍（§8.3） |
| `[object Object]` / 裸 JSON 进 iframe | 信封被当 HTML 塞 srcDoc | 区分 text/html 与信封，信封走 ErrorState（§7.2） |
| 跌日也显红 / 涨日也显绿 | 模板颜色写死（skill 自身 bug） | 占位符 + 数据区赋回原值；是否修 skill 由你定（§5.5） |
| 本地库类能力默认日期对不上 | 该用 `latest_local` 却用 `latest_published` | 本地库能力 `require_local=True`、默认 `latest_local`（§6.1） |
| 删了 `.pill` 的 `up` 类后结构指纹变 | `up/dn` 是死类、颜色来自内联 | 死类保留别删（§5.5） |
